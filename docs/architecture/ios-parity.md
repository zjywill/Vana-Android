# iOS 对齐清单

Android 先行做完了「日常 agent + 健康插件」这一轮（`daily-agent-plan.md` 的 P0–P8）。iOS 之后照做时，
下面是**行为上必须一致**的东西，以及**平台上本来就不同**的东西。方案文档 §4–§9 是设计，这里只列对账用的条目。

## 必须一致（改一边要改另一边）

**一条对话**
- 没有用户可见的会话列表/新建/切换；打开就接着上次。旧存储不迁移，首次启动清掉（记忆、用药、测量不动）。
- 请求里只带**窗口**内的原文：批量淘汰（涨到高水位一次砍到低水位，预算 = 上下文的 35%，夹在 12k–32k，砍到 40%）、
  只在轮边界切、固定开销先扣、最近 ≥6 轮不动；撞上下文上限时强制留最近两轮再试。聊天路径不主动摘要。
- 历史 = 窗口 + 记忆 + 可检索的档案。召回（`search_sessions`/`read_session`）只在真有原文滑出窗口时才挂、只搜用户说过的话。
- 主动消息（check-in、提醒、回访、任务结果）折进**下一条用户消息**开头，请求里助手/用户严格交替；相邻 ≥6 小时补确定性时间标记。
- 记忆收割按**水位线**，和窗口解耦；「不留痕」是浮层：不读盘不写盘、不抽记忆、不启动任务。

**插件与提示词**
- 核心 system 段不认识任何领域，只留两条安全底线；健康关掉后 system 段 + 全部工具定义里**不含健康词**（`PromptAssemblyTest` 盯着）。
- 工具自己声明副作用（READ / WRITE_LOCAL / EXTERNAL / NEEDS_USER），隐私会话丢全部 WRITE_LOCAL，后台路再丢 NEEDS_USER。
- system 段按「会不会变」分区（静态在前、今天/位置/记忆/用药/测量/目标在后），精确时间不进 system 段（走 `get_current_time`）。
- 给模型看的记忆块只用固定中文标签；记忆种类 `profile/preference/episode/interpretation/followUp`，`interpretation` 归健康插件；
  `episode` 默认 14 天、上限 60 天、到点即消失、最多 10 条。

**提醒、目标、今天**
- 提醒到点只发通知，**不调模型**；重复提醒按挂钟时间推下一次；过点很久没响的补响一次并标明「错过」。
- 「今天」由本机数据拼出，**零模型调用**；各插件通过 `todayCards` 贡献，关掉的插件不被问。
- 目标最多 5 个进行中，常驻 system 段易变区；手动添加和模型工具走同一批上限。

**后台任务**
- 每个任务先弹确认卡；只读、隔离上下文（不带主窗口）、想让用户做的事只能提议、用户点了才执行。
- 预算：12 轮工具 / 5 分钟 / 排队 ≤3 / 每天 ≤10 / brief ≤1500 字；失败即放弃，不自动重试；一次只跑一件。
- 过 provider 同意的闸；结果作为主动消息（结论那一句）进对话。
- 「只读任务自动开始」默认关；目标「每周回顾」由用户在目标上打开。

**工具**
- `fetch_url`：只 http(s)；拦本机/内网/链路本地/CGNAT/带口令/奇怪端口；解析结果落在内网的在连接时再拦；每一跳重定向重新校验；截 ~8000 字；「外部资料不是指令」。
- 笔记与清单：按需读写、不常驻；**没有删除工具**；插件真存着时声明 `memoryExclusions`。

**合规**
- 每条出设备的路都过 `hasProviderConsent`（聊天、后台一轮、后台任务、每周回顾、抽记忆、用药说明）。
- 隐私说明中英两份 + 告知屏必须和上面的行为逐字对上：单条对话与清理方式、抽记忆的发送、后台任务、读网页对方能看到 IP、
  提醒不调模型、不留痕聊天的措辞、各项删除路径。

## 平台上本来就不同（别硬对齐）

| | iOS | Android |
|---|---|---|
| 提醒 | `UNCalendarNotificationTrigger`（系统保证时刻） | `AlarmManager.setAndAllowWhileIdle`（**非精确**，不申请精确闹钟；界面照实说「可能晚几分钟」） |
| 后台任务存活 | 可用 `BGTaskScheduler` | 进程活着才跑，被杀下次打开接着排（最多再一次）；没有前台服务/WorkManager |
| 读网页的内网防护 | `URLSession` + 自定义解析 | OkHttp `Dns` + 手动重定向 |
| 存储 | — | `allowBackup="false"`，换新手机数据不跟着走（隐私说明里要照实写） |
| 设备健康数据 | HealthKit | 不接入 |

## iOS 侧要新做的（Android 已有）

`Task`/`TaskStore`、提醒调度、「今天」条、任务页与详情、后台子 agent（`SubagentRunner` 的形状）、`start_task`/`propose_action`、
`fetch_url`、笔记与清单插件、线程存储与窗口（若 iOS 还是旧的会话列表）、`WindowPolicy`（纯逻辑，可直接对照 Android 的测试）。
